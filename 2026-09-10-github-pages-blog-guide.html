为什么选择 GitHub Pages？

GitHub Pages 是 GitHub 提供的免费静态网站托管服务，非常适合个人博客、项目文档、作品集展示。相比传统的服务器托管，它有几个显著优势：

  • 零成本：完全免费，无需购买服务器或域名（可用 github.io 子域名）
  • 免维护：无需运维服务器、配置 Nginx、申请 SSL 证书
  • 版本控制：内容即代码，Git 管理所有历史版本
  • 自动部署：推送到 main 分支自动触发构建发布
  • 全球 CDN：GitHub 自带全球分发网络，访问速度快

快速搭建步骤

1. 创建仓库

在 GitHub 创建名为 用户名.github.io 的公开仓库（必须是这个命名格式才会作为用户站点）。

2. 本地初始化

git clone https://github.com/用户名/用户名.github.io.git
cd 用户名.github.io

3. 创建首页

在根目录创建 index.html，GitHub Pages 会自动识别并作为首页：




    
    
    我的博客
    


    
欢迎来到我的博客

4. 推送部署

git add .
git commit -m "Initial commit: Add homepage"
git push origin main

几分钟后访问 https://用户名.github.io 即可看到网站上线。

推荐的目录结构

随着文章增多，建议按以下结构组织：

用户名.github.io/
├── index.html          # 首页（文章列表或简介）
├── style.css           # 通用样式
├── articles/           # 文章目录
│   ├── 2026-09-10-github-pages-guide.html
│   ├── 2026-09-08-vim-tips.html
│   └── ...
├── assets/             # 静态资源
│   ├── images/
│   └── favicon.ico
└── 404.html            # 可选：自定义 404 页面

部署与更新流程

日常写作流程很简单：

  1. 在 articles/ 目录创建新文章 HTML 文件
  2. 在 index.html 添加文章链接
  3. 提交推送：
git add .
git commit -m "新增文章：GitHub Pages 搭建指南"
git push origin main

GitHub Actions 会自动构建，通常 30-60 秒后新内容上线。

常见坑点与技巧

1. 推送失败时用 GitHub API 兜底

如果 git push 认证失败，不要反复重试，直接用 GitHub REST API 更新文件：

# Python 示例
import requests, base64, json

def update_file(token, owner, repo, path, content, message):
    url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
    headers = {"Authorization": f"token {token}"}
    
    # 先获取当前文件 SHA
    r = requests.get(url, headers=headers)
    sha = r.json().get("sha")
    
    # 更新文件
    data = {
        "message": message,
        "content": base64.b64encode(content.encode()).decode(),
        "sha": sha
    }
    requests.put(url, headers=headers, json=data)

2. 分支名不一致问题

本地可能是 master，远程是 main，推送时指定：

git push origin master:main

3. 自定义域名

在仓库根目录添加 CNAME 文件，内容为你的域名（如 blog.example.com），然后在 DNS 添加 CNAME 记录指向 用户名.github.io。

4. Jekyll 与纯 HTML 的选择

GitHub Pages 默认用 Jekyll 构建。如果你不想用 Jekyll（想要完全控制 HTML），在根目录创建空文件 .nojekyll 即可禁用 Jekyll 处理，直接托管静态文件。

结语

GitHub Pages 是程序员搭建个人品牌的最佳起点。零成本、零运维、版本可控，配合 Git 工作流，写作即部署。今天就创建你的第一篇文章吧！
